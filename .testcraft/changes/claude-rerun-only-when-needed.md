# claude/rerun-only-when-needed

只改了文字说明、或默认分支往前走了而相关文件没变时，不再重跑测试。三处：清单文件不算进证明记录；放水检查里跑测试得出的结果单独记，补理由不重跑；记录不再带"分叉点是哪个提交"，改成带相关文件在分叉点上的内容。原因见测试写法方案 5.4 的"记录"和 5.5 的"跑出来的结果单独记"。

## 证明方式

- 证明过以后只加了清单条目，不用重证 —— 新测试 `plugin/tests/craft/reuse.test.ts` 的"证明过以后只加了清单条目：不用重证"
- 默认分支往前走了、合了进来，证明用到的文件原来的样子没变的不用重证；变了要重证 —— 新测试 `plugin/tests/craft/reuse.test.ts` 的"证明过以后默认分支往前走了、合了进来：证明用到的文件原来的样子没变，不用重证；变了要重证"
- 放水检查缺理由没过，补上理由再查，旧版测试不重跑；又改了代码要重跑 —— 新测试 `plugin/tests/craft/reuse.test.ts` 的"放水检查缺理由没过，补上理由再查：旧版测试不重跑；又改了代码要重跑"
- 放水检查过了以后默认分支往前走了、相关文件没变，不用重查 —— 新测试 `plugin/tests/craft/reuse.test.ts` 的"放水检查过了以后默认分支往前走了、合了进来，相关的文件没变：不用重查"
- 证明过以后改了 testpace.json 里跑测试的 files 命令，要重证 —— 新测试 `plugin/tests/craft/reuse.test.ts` 的"证明过以后改了 testpace.json 里跑测试的 files 命令：要重证"
- 放水检查跑到一半判断不了的结果不记，再查还是没做完 —— 新测试 `plugin/tests/craft/reuse.test.ts` 的"放水检查跑到一半判断不了（新版测试在副本里也跑不过）：没做完的结果不记，再查还是没做完"
- 取文件在某个提交上的内容标识，名字里有特殊字符的按原名取 —— 新测试 `plugin/tests/craft/reuse.test.ts` 的"取文件在某个提交上的内容标识：名字里有方括号、星号、空格、中文的按原名取；那里没有的文件不在结果里"
- 取内容标识时 git 跑不成就报错，不当成那里没有这些文件 —— 新测试 `plugin/tests/craft/reuse.test.ts` 的"取内容标识时 git 跑不成（没有这个提交）：报错，不当成那里没有这些文件"
- 只改了测试、加了清单条目，代码没改时，放水检查不跑旧版测试（和只加改动记录一样） —— 新测试 `plugin/tests/craft/reuse.test.ts` 的"只改了已有测试的断言、加了一条清单，代码没改：放水检查一个测试都不用跑"
- 内容变了照旧要重跑（改了测试、改了代码、改了理由要重查结论、证明过程中内容改过不记） —— 已有检查（`plugin/tests/craft/prove.test.ts`、`plugin/tests/craft/weaken.test.ts`、`plugin/tests/craft/hooks.test.ts`、`plugin/tests/craft/review.test.ts` 本来就守着，没改，都通过）
- 残余风险：默认分支上改了这次没碰的文件、恰好让新测试抓不到错了，不会重证；放水检查里旧版测试在新代码上跑出来的结果也一样，不会重跑 —— 需要用户看：合并后的整组照样要全部通过，测试写法方案 5.4 记了这一条
