# 程序读写仓库外的位置时，测试用的要是它自己的那份

## 触发

- `plugin/src/**` 改到 `homedir\(\)`
- `plugin/src/**` 改到 `--global`
- `plugin/hooks/**`、`plugin/entry/**` 改到 `\$HOME`

## 怎么查

这次新读、新写的仓库外位置（家目录、全局 git 配置、agent 给的数据目录），在 `plugin/tests/helpers.ts` 里已经换成测试自己的临时目录，而且测试进程里直接调的代码和测试起的命令（`ENV`）两边都换了。跑之前先确认真实的那份是它该有的样子（固定入口：`testpace status` 显示"已放好"），留一份副本；跑一次相关测试，跑完用 `cmp` 和副本比内容。不只看修改时间：更早的一次运行可能已经把它换掉了，前后时间一样也看不出来。

换掉的位置别的工具也在用时（家目录里还有 npm 的下载缓存和用户设置），测试真起的外部工具要照样能用：模块边界的测试真起 layermap，它靠 npm 装自己。换完把真起外部工具的测试（`plugin/tests/wall/`）跑一遍，看用时有没有变长。

测试这一侧的隔离要比"会读写那个位置的代码"先落到默认分支，不能放在同一次改动里：放水检查（`testcraft weaken`）会把测试和测试辅助文件都换回分叉点的样子去跑新代码，分叉点上还没有隔离的话，新代码就写到真实的位置上。

## 来由

claude/rename-gatelight：加了"会话开始时把旧版本放的固定命令入口换成这一版的"，测试里直接调会话开始的判断，用的是真实的家目录，把用户机器上的 `~/.local/bin/testpace` 换成了还没发布的那一版，命令行的 testpace 用不了、合并门不检查，直到手动恢复。在测试辅助文件里补上隔离后又出了一次：放水检查拿分叉点上没有隔离的旧辅助文件跑新代码。隔离单独落地时整组卡住：家目录换掉后 npm 的下载缓存也跟着没了，模块边界的测试每个文件都重新联网下载 layermap。
