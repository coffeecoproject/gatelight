# 文档里不另写已定的规则：规则在测试里，文档只写为什么

## 触发

- `**/*.md`

## 怎么查

只看给人读的文档（设计文档、方案、README 这类）。给 agent 照着做的说明（技能、CLAUDE.md、AGENTS.md）不算。

把这次改到的段落逐段过一遍，看它写的是哪一种：

- 规则：什么情况下程序怎样、拦什么、放什么、报什么。这次已经写进测试的，删掉这段，以测试为准。
- 为什么这样定、否掉的做法、还没定的、怎么跑：留着。

一段里两种都有的，删掉规则那半句，只留原因。这次没改到的旧段落不用管。

## 来由

gatelight 接入 testcraft 时默认带的一条。testcraft 定了"规则写进测试后，合并时由做分支的会话把文档里写着这几条规则的段落删掉"，但只写在会话说明和技能里，合并时没有东西提醒，gatelight 自己连着两次合并都漏删了（0.20.1、0.21.0）。程序分不出一段文字是规则还是原因，只能在改了文档时提醒查一遍。
