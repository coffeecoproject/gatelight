# 同一个数只算一处：改了一个数怎么算，别处另算的一起改

## 触发

- `**/*.ts`、`**/*.tsx`、`**/*.js`、`**/*.jsx`、`**/*.mjs`、`**/*.py`、`**/*.go`、`**/*.java`、`**/*.sql` 改到 `[Aa]mount|[Pp]rice|[Tt]otal|[Ff]ee\b|[Tt]ax|[Bb]alance|[Cc]ost|[Rr]efund|[Aa]ccru|金额|单价|总价|成交价|费用|手续费|税|分成|计提|余额|成本|退款|返还|应收|应付|实付|合计`

## 怎么查

这次改了某个数怎么算的（金额、计提、分成、税、余额这类，或者某个状态下它是多少），在整个仓库里找这个数还在哪里算：

- 后台别的地方：结算、报表、导出、对账、退款这类，同一个模块里的也算。
- 前端：表单里的预览、页面上自己乘出来的数。

按算式用到的字段和状态（比如 `status === '作废'`、`rate`）搜，不只按函数名搜：另算的那份往往没调同一个函数。

找到另算一份的：

- 后台：改成调同一个函数，只留一处回答"这个数现在是多少"。
- 前端：由后台算好传过来。必须在前端先算的（输入时实时显示），合并前的测试里比对前后端对同一组输入算出的数。
- 测试：这个数在每个读到它的地方（比如单元账、结算单、页面）各断言一次，不只测这次改的那一处。

项目里别的要紧的数（库存、积分、名额这类）不叫上面这些名字的，在"## 触发"里加一行写上它的名字。

## 来由

gatelight 接入 testcraft 时默认带的一条。CrocWork 的 MCN 断点修复（`9b21af3e`）定了"全案来的单做完后作废，签约方分成照旧记着"，只改了单元账；结算单的起草、重算、确认三处还各写着"作废就是 0"。单元账记 3000、结算单计提 0，会计照实付补一笔，成本就记成了两倍。回头一查，净额、平台应收、个税和分成的前端预览也各算一套。几处都在同一个模块里，lint 和模块边界看不出来；测试只测改了的那一处，也看不出来，只能在改了怎么算时提醒查一遍。
